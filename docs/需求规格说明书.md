# 交易策略管理系统 - 需求规格说明书

## 一、项目概述

### 1.1 项目背景
构建一个面向金融交易领域的策略管理平台，支持多角色用户登录，实现对交易策略的创建、编辑、审核、启停等全生命周期管理。

### 1.2 技术栈
- **前端**: Vue 3 + Element Plus + Vue Router + Pinia
- **后端**: Spring Boot 3.x + Spring Security + MyBatis-Plus
- **数据库**: MySQL 8.0
- **部署**: Docker Compose

---

## 二、功能需求

### 2.1 用户认证与权限管理

#### 2.1.1 用户角色定义
| 角色 | 权限 | 说明 |
|------|------|------|
| 系统管理员 (ADMIN) | 所有权限 | 管理用户、系统配置 |
| 策略管理员 (MANAGER) | 策略审核、策略启停、查看报表 | 管理策略生命周期 |
| 策略交易员 (TRADER) | 创建策略、编辑策略、查看自己策略 | 策略开发与维护 |
| 访客 (VISITOR) | 查看公开策略 | 只读访问 |

#### 2.1.2 功能列表
1. **用户登录**: 用户名/密码登录，JWT Token 认证
2. **密码管理**: 修改密码、重置密码（管理员）
3. **权限控制**: 基于 RBAC 的菜单和按钮级权限控制
4. **会话管理**: Token 自动刷新、登出

### 2.2 交易策略管理

#### 2.2.1 策略实体属性
| 字段 | 类型 | 说明 |
|------|------|------|
| 策略ID | Long | 主键，自增 |
| 策略名称 | String | 唯一，2-50字符 |
| 策略代码 | String | 唯一标识，如 STR-2024-001 |
| 策略类型 | Enum | 趋势跟踪、均值回归、套利、其他 |
| 交易标的 | String | 股票、期货、外汇等 |
| 策略描述 | Text | 详细说明 |
| 策略参数 | JSON | 可配置参数 |
| 风险控制 | JSON | 止损、止盈、仓位控制 |
| 状态 | Enum | 草稿、待审核、已发布、已暂停、已归档 |
| 创建人 | Long | 关联用户ID |
| 审核人 | Long | 关联用户ID |
| 创建时间 | DateTime | |
| 更新时间 | DateTime | |

#### 2.2.2 功能列表
1. **策略创建**: 填写策略基本信息、参数配置、风险控制
2. **策略编辑**: 仅草稿状态可编辑，已发布需先暂停
3. **策略审核**: 管理员审核通过/拒绝
4. **策略启停**: 启动策略执行、暂停策略
5. **策略归档**: 历史策略归档
6. **策略查询**: 多条件筛选、分页查询
7. **策略详情**: 查看完整策略信息

### 2.3 系统管理

1. **用户管理**: 增删改查用户，分配角色
2. **角色管理**: 角色定义与权限分配
3. **操作日志**: 记录关键操作
4. **系统监控**: 策略运行状态监控（模拟）

## 三、非功能需求

### 3.1 性能需求
- 页面响应时间 < 2秒
- 支持并发用户 50+
- 数据库查询优化，常用查询建立索引

### 3.2 安全需求
- 密码加密存储（BCrypt）
- JWT Token 安全传输

- 系统可用性 > 99%
- 友好的错误提示
- 表单输入校验
- 操作确认机制

### 3.4 可维护性需求
- 代码分层清晰
- RESTful API 规范

### 4.4 数据库设计

#### 4.4.1 用户表 (sys_user)
```sql
CREATE TABLE sys_user (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL UNIQUE COMMENT '用户名',
    password VARCHAR(100) NOT NULL COMMENT '密码',
    real_name VARCHAR(50) COMMENT '真实姓名',
    email VARCHAR(100) COMMENT '邮箱',
    phone VARCHAR(20) COMMENT '电话',
    status TINYINT DEFAULT 1 COMMENT '状态: 0-禁用 1-启用',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_username (username),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

#### 4.4.2 角色表 (sys_role)
```sql
CREATE TABLE sys_role (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    role_code VARCHAR(50) NOT NULL UNIQUE COMMENT '角色编码',
    role_name VARCHAR(50) NOT NULL COMMENT '角色名称',
    description VARCHAR(200) COMMENT '描述',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='角色表';
```

#### 4.4.3 用户角色关联表 (sys_user_role)
```sql
CREATE TABLE sys_user_role (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL COMMENT '用户ID',
    role_id BIGINT NOT NULL COMMENT '角色ID',
    UNIQUE KEY uk_user_role (user_id, role_id),
    FOREIGN KEY (user_id) REFERENCES sys_user(id),
    FOREIGN KEY (role_id) REFERENCES sys_role(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户角色关联表';
```

#### 4.4.4 交易策略表 (trading_strategy)
```sql
CREATE TABLE trading_strategy (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    strategy_name VARCHAR(50) NOT NULL COMMENT '策略名称',
    strategy_code VARCHAR(50) NOT NULL UNIQUE COMMENT '策略代码',
    strategy_type VARCHAR(20) NOT NULL COMMENT '策略类型',
    trading_symbol VARCHAR(100) COMMENT '交易标的',
    description TEXT COMMENT '策略描述',
    parameters JSON COMMENT '策略参数',
    risk_control JSON COMMENT '风险控制配置',
    status TINYINT DEFAULT 0 COMMENT '状态: 0-草稿 1-待审核 2-已发布 3-已暂停 4-已归档',
    creator_id BIGINT NOT NULL COMMENT '创建人ID',
    reviewer_id BIGINT COMMENT '审核人ID',
    review_time DATETIME COMMENT '审核时间',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_status (status),
    INDEX idx_creator (creator_id),
    INDEX idx_strategy_type (strategy_type),
    FOREIGN KEY (creator_id) REFERENCES sys_user(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='交易策略表';
```

#### 4.4.5 操作日志表 (sys_operation_log)
```sql
CREATE TABLE sys_operation_log (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT COMMENT '用户ID',
    username VARCHAR(50) COMMENT '用户名',
    operation VARCHAR(100) COMMENT '操作描述',
    method VARCHAR(200) COMMENT '请求方法',
    params TEXT COMMENT '请求参数',
    ip VARCHAR(50) COMMENT 'IP地址',
    duration INT COMMENT '执行时长(ms)',
    status TINYINT COMMENT '状态: 0-失败 1-成功',
    error_msg TEXT COMMENT '错误信息',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_user_id (user_id),
    INDEX idx_create_time (create_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='操作日志表';
```

### 4.5 API 接口规范

#### 认证接口
- `POST /api/auth/login` - 用户登录
- `POST /api/auth/logout` - 用户登出
- `GET /api/auth/info` - 获取当前用户信息

#### 策略接口
- `GET /api/strategy` - 策略列表查询
- `GET /api/strategy/{id}` - 策略详情
- `POST /api/strategy` - 创建策略
- `PUT /api/strategy/{id}` - 更新策略
- `DELETE /api/strategy/{id}` - 删除策略
- `POST /api/strategy/{id}/submit` - 提交审核
- `POST /api/strategy/{id}/review` - 审核策略
- `POST /api/strategy/{id}/start` - 启动策略
- `POST /api/strategy/{id}/pause` - 暂停策略
- `POST /api/strategy/{id}/archive` - 归档策略

#### 用户接口
- `GET /api/user` - 用户列表
- `POST /api/user` - 创建用户
- `PUT /api/user/{id}` - 更新用户
- `DELETE /api/user/{id}` - 删除用户
- `PUT /api/user/{id}/password` - 修改密码
- `PUT /api/user/{id}/roles` - 分配角色

#### 角色接口
- `GET /api/role` - 角色列表
- `GET /api/role/{id}/users` - 角色下的用户
